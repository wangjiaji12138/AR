# POI-Recognizer 待检查与优化清单

更新日期：2026-10-18。本文记录审查结论和下一步约束，不表示相关优化已经实现或验证。

## 当前约定

- 可以重新设计训练流程，不再强制每次从官方权重完整执行 ReCTS → LSVT 四个训练任务。
- 优先复用已有训练权重做基线、推理和小规模微调；暂不以换模型结构、扩字典或从头训练为首选。
- 目标执行环境为路端 GPU；训练优化和推理的显存、速度均以实际路端设备验证。现有 A800 测量仅作参考，不作为路端指标。
- 训练优化使用现有训练数据的 **1/5**。暂按“各数据集原训练划分内抽取 20% 原图，再生成检测标签和识别裁剪”执行，而不是检测、识别分别随机抽样。
- 验证集保持固定，优先使用完整原验证集，以便和已有模型公平比较；测试集继续隔离，不参与调参。如路端验证成本过高，可另设固定开发子集，但最终复核仍回到完整验证集。
- 原始数据、官方源码、已有权重和已有训练产物保持只读，新数据清单、模型与报告写入独立目录。
- 本文仅整理待办，不启动训练、导出、推理或测速任务。

## P0：先修评估与训练／推理一致性

### 1. 检测分辨率策略不一致

- [ ] 统一验证和实际推理的缩放参数。当前训练验证默认短边不足 736 时放大；整图推理却限制最长边 960。
- [ ] 在实际路端照片上统计缩放后的店名字高，检查远处、小字漏检；比较少量分辨率档位及必要的区域／切片方案，同时记录延迟。
- [ ] 对比检测 Precision、Recall、Hmean 和小字召回，避免仅提高速度却丢掉目标文字。

证据：`src/poi_recognizer/evaluate.py::build_predictor`、实际 `det.yml` 及官方 `DetResizeForTest`。策略差异已确认；造成的精度损失待测。

### 2. 识别宽度与长文本策略不一致

- [ ] 统一识别训练、裁剪验证和整图推理的缩放规则。当前训练／验证固定 320×48，宽文本被横向压缩；推理会按宽高比扩展宽度，320 并非上限。
- [ ] 检查宽高比分组、宽度档位，以及超长行切分／结果合并；不能简单把推理宽度截到 320。
- [ ] 同步检查最大标签长度、NRTR 起止标记和 CTC 时间步限制，避免只放宽长度过滤却让标签不可训练。
- [ ] 分别统计短店名、长店名、电话号码和长广告行，确认问题是否集中在长文本。

证据：`training.py::training_config`、`dataset.py::recognition_exclusion`、官方识别 resize。当前最多接受 23 字符；LSVT 训练与验证合计过滤 2498 条长文本。118 个保留识别验证裁剪中有 17 个宽高比超过 320/48；96 个整图预测框中有 40 个超过该比例。不能将这些样本比例外推为全量比例。

### 3. 建立可复现的完整评估

- [ ] 为精简后的训练目录提供从原始数据和既有划分恢复完整验证输入的入口，避免默认只能评估保留的 1%。
- [ ] 固定原图 ID、预处理、匹配规则和版本；三份权重在同一批图片上比较。
- [ ] 分开报告检测、GT 裁剪识别、预测框裁剪识别、整图端到端和店名指标；POI 地图匹配单独计分。
- [ ] 保留漏检、误检、错字及成功样例的原图对照，不能只展示成功图片。
- [ ] 保留完整验证清单及过滤统计；缓存可以清理，不能让清理操作阻断后续复核。

证据：`evaluate.py` 自动切换到 `data/examples/`；`retention.py` 删除全量准备标签和裁剪。原始数据仍在，可重建，不是原始数据丢失。

## P1：复用权重，用 1/5 数据重新设计微调

### 4. 固定抽样与数据覆盖

- [ ] 在既有训练划分内按原图抽样，固定 seed=42，保存源划分、抽样 ID、比例和样本统计。
- [ ] 按原训练 ID 数量的 20% 抽取：ReCTS 计划 2800 张，LSVT 计划 2100 张；有效数量在缺图、坏图和标签过滤后另报，不从验证／测试集补样。
- [ ] 检测与识别从同一批入选原图生成数据。识别裁剪数量不要求恰好为原裁剪数量的 20%。
- [ ] 检查中文／英文、长度、字高、宽高比、模糊、倾斜和特殊字体的覆盖，避免小数据只剩容易样本。
- [ ] 验证集、测试集和原始数据不因缩减训练集而被删除或重新混分。

### 5. 检查微调收益与遗忘

- [ ] 默认从已有 LSVT 最佳 det／rec 权重初始化，先测不训练的基线，再决定是否微调。
- [ ] ReCTS 最佳和官方权重作为对照，不要求所有实验都重新跑两阶段。
- [ ] 比较小规模混合 ReCTS／LSVT 微调与单域微调；在两个固定验证集上都检查，确认是否改善目标域并避免明显遗忘。
- [ ] 检测和识别分别设置学习率、warmup、训练步数与早停／选优条件；不机械沿用统一学习率和每阶段 50 轮。
- [ ] 按实际更新步数和验证收益控制实验成本；20% 数据不意味着耗时或精度必然按比例变化。

当前两阶段顺序微调的收益和遗忘均未被同图对照证明，不能直接认定 ReCTS 训练无效。

### 6. 恢复合适的训练覆盖与裁剪鲁棒性

- [ ] 检查恢复识别多尺度和 `RecConAug` 的可行性，先解决拼接长度约束；检测 `CopyPaste` 先解决原生多边形兼容性，再决定是否采用。
- [ ] 对训练集生成适度框偏移、背景边缘和轻微截断扰动，或使用训练集上的检测预测框，缩小 GT 裁剪与实际预测裁剪的差距。
- [ ] 对相同文字比较 GT 裁剪与预测裁剪的识别结果，确认错字来自框、缩放还是识别模型。
- [ ] 单独检查弯曲、透视和竖排样本。最小旋转外接矩形不能拉直弯曲文本，但不应无条件给所有图片增加重型矫正模块。

证据：`training.py` 移除了 `RecConAug`／`CopyPaste`，并固定单尺度；`geometry.py::crop_text` 负责 GT 裁剪。当前仍保留 `RecAug`，不是完全没有数据增强。恢复增强的收益尚待验证。

## P1：路端 GPU 推理优化

### 7. 明确目标设备与常驻推理方式

- [ ] 记录路端 GPU 型号、显存／共享内存、功耗模式、系统、CUDA、TensorRT 和 Paddle 版本；不能把 A800 结果直接用于设备选型。
- [ ] 模型提前导出，进程初始化时加载一次，后续图片复用预测器。
- [ ] 将推理入口与评估、模型导出、画图和报告生成分离。不能每张图启动一次当前 `evaluate.sh`。
- [ ] 分别测启动时间、稳定单张延迟、连续吞吐、P95 和进程实际内存／显存。

当前仅有离线评估入口；每次评估会复制权重、导出和初始化。此前 91.1 ms 不包含这些步骤。

### 8. 后端、批处理与宽度控制

- [ ] 在目标设备验证 FP16／TensorRT 与现有动态输入的兼容性，对照 FP32 的精度和延迟，再决定启用。
- [ ] 测试识别 batch 与按宽高比分组策略，检查超长框造成的输入扩张与 padding 成本；现有官方识别器已经做了宽高比排序，不重复实现相同功能。
- [ ] 区分测速与生产路径。阶段同步可用于准确计时，但生产路径避免仅为统计而加入的全局同步。
- [ ] 根据实际拍照频率决定是否需要流水处理／并发，不为单路低频拍照盲目增加批处理等待。
- [ ] 在吞吐测试中检查读图、裁剪和 GPU 是否互相等待，不预先承诺具体加速倍数。

证据：`evaluate.py::build_predictor` 固定识别 batch=6、关闭 TensorRT；`infer` 串行执行检测、CPU 裁剪和识别，并在阶段边界同步 GPU。

### 9. 完善测速与内存统计

- [ ] 使用固定代表性图片充分预热、多轮测量，记录字框数量和输入尺寸，同时测实际连续运行负载。
- [ ] 分别报告模型计算、完整 OCR、读图解码及拍照到结果的延迟，不能混用。
- [ ] 同时读取进程／设备级显存和框架分配器统计；共享内存设备按其实际口径记录。此前 Paddle 已分配峰值约 211 MiB、预留约 385 MiB，不能当作完整 GPU 进程占用，也不能相加。
- [ ] 质量约束和速度一起验收，避免用降低分辨率、漏掉文字或只测短文本换取好看的延迟。

## 暂不直接归因或优先实施的事项

- CTC 不等于没有上下文能力；当前训练带 NRTR 辅助分支。不能因为错字就认定必须改为注意力解码或大语言模型纠错。
- det → crop → rec 仍是成熟方案，mobile 模型也不是天然错误。先统一处理与评估，再决定是否换更强模型。
- 不因未启用方向分类、矫正或置信度过滤，就认定它们是全部精度损失来源。它们各有适用场景，阈值还会改变精确率／召回率取舍。
- 不把增大训练轮数、恢复全部增强或扩大 batch 当成必然提升；每项变化都要有固定基线。

## 首轮执行顺序与验收

1. 明确路端硬件，建立可复现评估；优先评估已有最终权重，补充 ReCTS／官方权重对照。
2. 统一检测缩放、识别宽度及长文本处理，再建立新的精度与延迟基线。
3. 固定抽取 20% 训练原图，从已有权重开展小规模微调；每次只改变一类因素，按验证结果决定保留。
4. 在路端 GPU 比较 FP32 与可用的加速后端，使用同一批图片和质量约束验收。
5. 补充真实路端照片上的店名及 POI 匹配结果，再决定是否需要模型升级。

验收至少包含：固定数据范围、权重来源、过滤统计、检测 P/R/F1、裁剪识别 Acc／编辑相似度、整图 P/R/F1、店名结果、对照图、目标设备平均／P95 延迟和峰值内存。目标阈值由业务延迟预算及实际基线确定，本文不预设未经验证的精度或加速承诺。
