# POI-Recognizer 指南

遵循根 [AGENT.md](../AGENT.md)。这是一个简单的离线 OCR 小功能：ReCTS 训练 det/rec → train_images 有监督微调 det/rec → 查看真实图片效果和速度。按需求直接实现，不走方案审批，不搭建完整训练平台。

## 实现原则

- 使用 Conda `myenv`、Python 3.10、Paddle GPU 3.1.1，以及本地 PaddleOCR v3.2.0 官方源码；模型为 PP-OCRv5 mobile det/rec。
- 尽量复用官方训练、导出和推理工具。离线推理、图片可视化、指标和测速属于合理功能范围，不再被旧的“仅训练”约定禁止；目前已实现哪些，以代码及 README 为准。
- 不顺带扩字典、改模型结构、加模型 hook、恢复控制器或数据管理框架。不做参数搜索、自动早停、复杂增强和多组对照平台。共享动态识别 resize 与批内 padding 通过项目启动器注册为数据算子，官方源码保持只读。
- 训练入口保持一个命令，先准备 ReCTS 并训练检测/识别，再从各自最佳权重初始化 LSVT 检测/识别微调；重置第二阶段优化器。阶段失败即退出。GPU 不可用时明确报错，不静默改用 CPU。
- 训练和验证在终端用进度条显示，文件只保留每轮摘要、指标及必要诊断，避免逐 batch 日志膨胀。

## 数据与评估

- 按用户 2026-10-18 审视后的要求：ReCTS 有标注 train、LSVT 本地编号 0–14999 分别按排序 ID、seed=42 抽取 1/10 原图，再按 7:1:2 重新划分 train/val/test。ReCTS 读取逐图 JSON 的 lines，不使用无标注官方 test。先抽样和划分再检查文件，不补号、不挪集合；测试集不参与训练和开发验证。新划分不能直接与历史指标比较。
- 原图、原始标签、官方源码、预训练权重和已有产物只读，新运行和报告使用独立输出目录。
- 缺图、坏图跳过并报告。检测保留有效原生多边形，忽略文字标为 `###`，空或全忽略图像不进入检测训练。
- 识别使用逐实例裁剪，多点框使用最小旋转外接矩形；超长、未知字符、控制字符和无效几何样本整条跳过并记录，不删字后训练。质量报告注明被过滤样本及统计范围。
- 分清检测质量、标注裁剪识别质量和整图端到端质量。不能用标注裁剪准确率代替真实街景效果，也不能把编辑相似度叫作字符准确率。
- 测速说明设备、输入、batch 和计时范围；区分训练吞吐、验证 fps、完整推理耗时。可视化应能看到预测文字及漏检、误检、错字，不只展示成功样例。

## 运行与检查

- 用户自行运行数据准备、训练、GPU 冒烟和模型评估/测速；代理整理代码与命令、读取已有产物，不自动启动或中断模型任务。用户明确要求代跑时再执行。
- 训练不再自动精简为 1% 样例，保留这次抽样数据的标签、裁剪和划分。训练/验证/推理共用识别等比例动态宽度，检测验证与推理最长边 960；默认启用 O1 混合精度。
- 两阶段默认各训练 50 epoch；`--smoke` 每阶段使用 train/val 各至多四张可解码图片、det/rec 各训练一个 epoch。使用方法见 [README](README.md)。
- 代码改动运行相关合成 pytest 和必要的 Ruff、Black、Mypy 检查；不为文档或低影响修改增加测试，不把 GPU 冒烟通过当作质量或部署性能达标。
- 使用说明统一维护在 README，不再新增重复的方案、计划或交接文档。
