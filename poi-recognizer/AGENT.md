# POI-Recognizer 智能体指南

本指南适用于 `poi-recognizer/`，未覆盖的事项遵循根目录 [AGENT.md](../AGENT.md)。当前文件名为 `AGENT.md`，使用依赖 `AGENTS.md` 自动发现的工具时必须显式加载；后续统一命名时同步更新引用。

本文补全原始需求，新增的默认规则作为后续 Spec 的方案基础，不表示实现或训练已经完成。业务实现前按根指南第 11 节准备 `spec.md`、`plan.md` 并确认实施范围；完善本文本身不触发训练、依赖安装或数据重写。

## 1. 职责、边界与当前状态

- 使用 PaddleOCR 检测并识别 LSVT 街景图像中的文字，支持 GPU 微调、评估与批量推理。
- 每张图像输出识别文本和一个整体 bbox；有标签的离线评估同时输出真实文本和真实整体 bbox。
- “符合 Label”指通过标注评估识别质量，不承诺逐字正确，不允许用真实标签补写、纠正或筛选推理结果。
- 当前范围是离线图像处理；POI 名称筛选、地图查询、空间关联、视频跟踪及车路通信不在本次范围内。街景中的所有可辨认文字均是识别对象，不能自行只保留店名。
- 识别部署在路侧；训练设备可以独立配置。未确定路侧设备前，不宣称模型满足实时或资源指标。
- 2026-10-13 只读核查：`src/` 尚无实现；原始标签为 `data/photo-lsvt/train_labels.json`，包含 30,000 个图像键，编号为 `gt_0` 至 `gt_29999`。`train_images/` 当前仅发现 494 个图像文件，完整数据是否已解包到其他目录尚未核实。以上是核查快照，启动时必须重新校验。

## 2. 路径、环境与依赖

本文中的 `data/...` 均相对 `poi-recognizer/`，配置文件中的相对路径也以该子功能根目录为基准，不能随启动工作目录变化。

| 用途 | 默认路径 |
| --- | --- |
| 原始图像（只读） | `data/photo-lsvt/train_images/gt_X.jpg` |
| 原始标签（只读） | `data/photo-lsvt/train_labels.json` |

| 权重、训练配置与日志 | `data/outputs/photo-lsvt/<run_id>/checkpoints/` 等 |

- 图像根目录、标签路径、派生目录、输出目录、设备与模型路径均可配置；不得硬编码绝对路径。

- 基于官方中文预训练检测与识别模型微调，优先评估适合路侧部署的轻量模型。具体模型、权重来源、许可、校验摘要、字符字典及训练代码版本记录在 Spec 和运行元数据中，不在未验证时指定版本。
- 正式训练必须使用 GPU；启动检查 GPU 可用性和所选设备，不可用时明确失败，禁止静默切换 CPU。CPU 仅可用于明确标记的数据检查或逻辑测试。
- 不自动安装依赖、下载权重或解压真实数据。实施计划明确这些动作及资源需求后在授权范围内执行。
- 原始数据及模型权重不提交 Git；落实 `.gitignore`，小型合成测试夹具例外。裁剪、缓存和导出不得覆盖原始图像或标签。

## 3. 输入契约与标签分块

### 3.1 原始标签

标签是 UTF-8 JSON 对象，图像键为 `gt_X`，`X` 为非负整数，对应图像 `gt_X.jpg`；值为逐文字实例数组。例如：

```json
{
  "gt_0": [
    {"transcription": "商店", "points": [[10, 20], [90, 20], [90, 50], [10, 50]], "illegibility": false}
  ]
}
```

- `transcription`：字符串；`points`：原图像素坐标的四点多边形，每点为 `[x, y]`；`illegibility`：布尔值，表示文字不可辨认。
- 坐标原点位于原图左上角，x 向右、y 向下。校验类型、有限数值、非退化多边形及图像边界，不把归一化坐标当成像素坐标。
- 缺字段、重复 JSON 键、数字编号冲突、缺失/损坏图像、越界或退化标注都必须列入检查报告。不得静默跳过、截断坐标或将错误当成空标注。
- `illegibility=true` 或文本为 `###` 的实例作为忽略区域，不用于识别监督、真实文本汇总或真实整体 bbox。空白转录与其他异常标注需报告并按 Spec 的显式规则处理。
- 空数组或全部实例被忽略的图像仍保留在清单中；训练适配器按所选模型能力处理并记录计数，不能虚构正样本。
- 标签不携带时间戳、相机编号或定位。不得从 `X` 推断时间或拍摄顺序；未来接入实时图像时另行定义带版本的契约，明确时间戳单位/时区、相机标识及定位来源。

### 3.2 分块规则

- 分块依据图像数字编号 `X` 的固定区间，而非累计记录数量：块号为 `X // 1000`，块区间为 `[块号*1000, 块号*1000+999]`，即 `0–999`、`1000–1999` 等。
- 每块仅保留本次选定数据集中属于该区间的图像记录，按 `X` 数值升序排序，禁止使用文件名字符串排序。区间内不足 1000 张时保留实际数量，不从其他区间补齐，也不补造缺失记录。
- 例如 `0–999` 仅有 400 张、`1000–1599` 有 600 张时，前一块仅保存这 400 张，后 600 张属于 `1000–1999` 块，不能移入前一块。
- 文件名使用固定区间边界，而非实际首末编号，如 `train_labels_00000_00999.json`，即使块内仅有 `gt_2` 和 `gt_900` 也使用此名称。空区间不生成块文件；其空缺通过清单体现。
- 每块保留原始 `gt_X -> 实例数组` 结构和标注内容。记录源文件摘要、块号、区间边界、块名、实际记录数、实际首末编号及分块规则版本。记录是否纳入本次数据集按第 4 节完整性或显式子集规则决定，不能借分块静默跳过缺失图像。
- 完整 30,000 条标签应形成 30 块。分块不等于训练/验证/测试划分，各块可包含不同集合的图像。
- 分块与划分属于一次显式的数据准备流程；训练加载器读取保存的清单，不在每轮训练中重新分块或随机划分。
- 重跑相同输入应生成相同内容，先写临时产物并验证，再发布到派生目录；输入变化生成新清单版本，不覆盖不匹配的既有产物。

## 4. 数据划分与防泄漏

- 在文字裁剪、增强及训练前，按原始图像划分 `train:val:test = 7:1:2`。先对图像编号数值排序，再使用固定种子（默认 `42`）打乱并划分；记录具体随机算法及版本，固定 seed 本身不能保证跨实现一致。
- 默认计数为 `train=floor(0.7*N)`、`val=floor(0.1*N)`、`test=N-train-val`。完整 30,000 张对应 21,000 / 3,000 / 6,000；出现空集合时正式训练失败，不靠复制样本补齐。
- 原图及其全部文字裁剪、增强版本只能属于一个集合。完全相同图像不得跨集合；如果发现连拍、近重复或来源组，先形成分组方案再调整划分，记录实际比例及原因。
- 默认正式流程检查全部标签对应图像可读；当前 494 个文件不能视为完整训练集。小样本试跑必须显式选择子集并记录选择清单、缺失数及比例，结果只代表该子集。
- 保存三个集合的图像 ID 清单、源标签摘要、图像内容摘要、种子、划分算法、过滤/分组规则和计数，生成稳定的 `split_id`。校验集合互斥、无重复并且并集等于本次选定的数据集。
- 训练集更新权重；验证集选择 checkpoint、阈值和超参数；测试集仅在方案冻结后用于最终评估。不得按测试结果反复调参，也不得让测试标签参与推理。

## 5. 训练与推理规则

- PaddleOCR 的检测与识别分别适配数据：检测使用整图逐实例多边形，识别使用可辨认实例的透视裁剪及对应转录。忽略区域按锁定版本的官方检测格式适配；不得把多段不相关文字合成一个训练框或一个识别裁剪。
- “所有文字统一成一个 bbox”只约束最终汇总输出。内部保留逐实例框、文本及置信度，用于诊断、排序和逐实例评估。
- 先评估预训练模型作为基线，再微调检测和识别模块。记录两者是否更新权重；仅微调识别时不能声称已训练检测模块。
- Spec 明确 batch size、学习率/调度、epoch 上限、增强策略、随机种子、验证频率、早停指标、checkpoint 选择指标和 OOM 处理。增强仅用于训练集，不能破坏文字标签或几何对应关系。
- 保存最优 checkpoint 及恢复训练所需的优化器、调度器和训练状态；续训校验模型配置、字符字典、数据清单与版本兼容性。
- 字符字典必须与预训练权重和训练标签兼容；未知字符需统计并明确处理，不能静默删掉。扩充字典时记录输出层适配与权重加载方式。
- 推理只读取图像及模型配置。真实标签通过独立评估步骤附加，不向推理函数传入真实文本或框。
- 检测和识别置信度阈值只用验证集确定并冻结。识别置信度为模型返回的 `[0,1]` 分数，不等同于经过校准的正确概率；保留分数与阈值配置。

## 6. 文本与整体 bbox 汇总

- 对超过冻结阈值的有效预测文字实例生成汇总；真实汇总使用所有可辨认实例。两侧使用同一坐标和排序规则，预测排序不能借用真实框。
- 第一版采用确定性排序：按实例轴对齐框的 `(y_min, x_min, y_max, x_max)` 排序，相同键按原实例序号打破平局，用换行符连接文本。此规则是可复现基线，不保证竖排或复杂布局的语义阅读顺序；改善排序须更新规则版本和评估记录。
- bbox 使用原图像素坐标的 `[x_min, y_min, x_max, y_max]`，由纳入汇总的所有多边形顶点求包围矩形。范围为 `0 <= x_min < x_max <= width`、`0 <= y_min < y_max <= height`，保留数值精度，不添加像素端点 `+1`。
- 推理中的缩放、旋转、裁剪坐标必须还原到原图后再求整体 bbox。存在异常实例时报告或标记错误，不能通过无记录地裁剪坐标掩盖问题。
- 无有效预测文字：`pred_text=""`、`pred_bbox=null`；无可辨认真值：`gt_text=""`、`gt_bbox=null`。空结果与读取/推理失败必须区分。

## 7. 输出契约（v1）

原需求的 `prediction.txt` 采用 UTF-8 JSON Lines 内容，每行一张图像；分块后文件名为 `prediction_<区间下界>_<区间上界>.txt`。字段不使用 `+` 或空格拼接，以免文本中的空格、换行或符号破坏解析。

| 字段 | 类型与含义 |
| --- | --- |
| `schema_version` | 必填字符串，固定为 `poi-recognizer.prediction.v1` |
| `image_id` | 必填字符串，如 `gt_0`；原需求的“图片 label”即此标识 |
| `split` | 必填字符串，`train` / `val` / `test` / `unassigned` |
| `status` | 必填字符串，`ok` / `no_text` / `error` |
| `pred_text` | 必填字符串，汇总预测文本 |
| `pred_bbox` | 必填，四个数值或 `null` |
| `gt_text` | 必填，有标签时为字符串，无标签时为 `null` |
| `gt_bbox` | 必填，四个数值或 `null` |
| `error` | 必填，成功时 `null`；失败时包含 `code`、`stage`、`message` 的对象 |

示例（合成数据）：

```json
{"schema_version":"poi-recognizer.prediction.v1","image_id":"gt_0","split":"test","status":"ok","pred_text":"商店","pred_bbox":[10,20,90,50],"gt_text":"商店","gt_bbox":[10,20,90,50],"error":null}
```

- 默认正式评估输出测试集；显式全量预测可处理全部集合，但指标必须按集合分别报告，不将训练集结果作为泛化能力。
- 预测结果沿用第 3.2 节固定编号区间，块内按 `X` 数值排序，采用区间边界命名并生成块清单。每块仅包含本次所选集合在该区间的图像，禁止跨区间补齐；空区间不生成文件。块数取决于所选图像覆盖的非空区间数，不能用总记录数除以 1000 推算；6,000 张测试图像可能分布在全部 30 个区间中。标签块与预测块按相同区间对应，实际记录数可因所选集合不同而不同。
- 每张选定图像恰好一行，失败也保留记录。失败时 `pred_text=""`、`pred_bbox=null`，真值可在成功解析标签时保留；不得伪装为 `no_text`。
- 数据准备或正式训练遇到无效输入时明确失败；批量推理可继续收集逐图错误，但运行汇总必须记录错误数量，有错误时退出码非零。错误类别至少区分输入无效、图像缺失、解码失败、模型加载、GPU 不可用、推理失败和输出写入失败。
- `no_text` 仅表示成功推理后无有效预测实例，与是否存在真值无关。无标签推理时真值两字段均为 `null`，不能虚构真实文字。
- 每个 `run_id` 保存运行配置、模型/字典摘要、`split_id`、阈值、排序规则、设备与软件版本、输出块清单及计数。新运行使用新目录；断点续跑校验元数据并去重，禁止无条件追加导致重复记录。
- 评估结果是显式授权的文本产物；正式日志默认只记录图像 ID、阶段、耗时和错误类别，不复制完整识别文本、原图或敏感绝对路径。

## 8. 评估与验收

- 训练前后在同一验证清单上对比基线；冻结模型和阈值后报告测试集结果。检测质量使用逐实例多边形匹配的 Precision、Recall、Hmean；识别质量区分真实裁剪上的模块结果与预测框上的端到端结果。
- 文本报告原始文本精确匹配率和字符错误率 `CER=(替换+删除+插入)/真实字符数`。默认仅统一 Unicode NFC 和换行编码，保留大小写、数字、标点及空白，不自行简繁转换。无真值字符的样本单独统计误报，CER 分母为零时标为不适用。
- 实例匹配、IoU 阈值、忽略区域处理、端到端匹配标准以及空结果指标口径在 Spec 中冻结。整体 bbox IoU 和整图文本匹配作为辅助指标，不能替代逐实例检测评估。
- 分别报告白天/低光、遮挡、运动模糊、竖排、无文字及不可辨认文字场景；分组来源和样本数可追溯，不凭空声明覆盖。报告误检、漏检、低置信度和常见字符混淆。
- 性能记录设备、软件/模型版本、图像尺寸、batch size、并发、预热、样本数、端到端与推理阶段的 p50/p95 延迟、吞吐、峰值内存及显存；GPU 计时须同步。缺目标设备时只报告实测限制。
- 质量和资源阈值待 Spec 确认，不能以“已输出文件”或“loss 下降”代替训练验收，也不能要求所有真实样本零错误。

实现至少验证以下可观察行为：

1. 合成乱序 ID（如 1、2、10），以及 `0–999` 内 400 张、`1000–1599` 内 600 张的稀疏数据：数值排序正确，两块分别保留 400 和 600 张，不跨区间填补。另验证边界编号 999/1000 分属相邻块、文件名使用固定区间边界、空区间不生成文件、无丢失/重复、标注内容与原始数据摘要不变。
2. 固定输入生成相同划分清单；比例计数正确、三个集合互斥、裁剪和增强不跨集合，缺失图像被报告。
3. bbox 汇总、坐标还原、忽略实例、空结果、异常标注及含换行/中文的输出均符合契约；每行可独立解析并对应一个图像 ID。
4. GPU 上完成经授权的小样本训练、保存/恢复 checkpoint、导出及独立图像推理；真实完整数据验收单独记录，不能用模拟或小样本结果替代。
5. 输出分块的总记录数等于所选图像数，每条记录编号均位于所在文件的固定区间，稀疏块不跨区间补齐；错误记录可追踪；基线与微调结果、固定测试指标和资源报告齐全。

## 9. 实现布局与命令落地要求

- 实现采用 `src/poi_recognizer/` 包布局，明确安装/导入方式；禁止测试临时修改 `sys.path`。
- 准备 `spec.md`、`plan.md`、配置示例、依赖清单、`tests/` 及使用说明。工具遵循根指南的 pytest、ruff、black 和类型检查约定。
- 数据准备、训练、评估和推理提供独立入口，覆盖配置校验、设备选择、范围选择和错误退出；安装、启动、测试、检查命令须实际验证后记录。
- 当前没有可运行入口或已验证命令，不将拟议 CLI 或官方示例直接写成项目现有能力。数据准备检查可用合成夹具，训练/推理验收使用经确认环境和 GPU。
- 有跨模块接口时在 `shared/contracts/` 登记版本；不导入 POI-Querier 内部类或工具，不写入 `.gpkg`。

## 10. 待确认项与已知陷阱

- 实施前确认：完整图像位置及许可、Conda/Python/GPU 环境、PaddleOCR 与 PaddlePaddle 兼容版本、预训练模型/字典、训练预算、超参数及质量目标。
- 路侧部署前确认目标设备、延迟与内存预算；实时输入和空间关联另行制定契约。
- 原图缺失时，标签总数不等于可用训练样本数；不能默认把目录中的 494 张当成 30,000 张已齐备。
- 分块用于存储组织，随机划分用于评估隔离，两者不得混淆。JSON 对象原始顺序不代表编号顺序。
- 全图汇总框可能覆盖大片无文字区域；仅看整体框 IoU 会掩盖漏检和文字错误。竖排及多行布局的排序误差需独立诊断。
- `###` 是忽略标记，不能作为普通文字训练；不能为匹配标签而把它加入输出。
- GPU 训练可存在非确定性；记录随机种子和确定性设置，不承诺相同 seed 得到逐位相同权重。
- 参考官方 [检测训练说明](https://paddlepaddle.github.io/PaddleOCR/v2.9.1/en/ppocr/model_train/detection.html)、[识别训练说明](https://paddlepaddle.github.io/PaddleOCR/v2.9.1/en/ppocr/model_train/recognition.html)。这些版本化文档用于理解训练流程；实施时必须对照实际锁定版本核验数据格式、命令和配置。
